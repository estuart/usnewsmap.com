# BUDA evaluation: validation, worker identity and Mac support

**Status:** source review and limited smoke tests; server spike pending · **Date:** 2026-10-14 · **Measured on:** BOINC `22bbebe08e2eaac5d5e88a6d93b88e800cb6341c`, wiki `7e16379966f15b9be85fc6206f875e02c70d6bc0`, docker_wrapper release 22 · **Issue:** [#481](https://github.com/tgoodyear/usnewsmap.com/issues/481)

## The question

Can BUDA replace the three signed Docker-wrapper apps while preserving their validation, worker image pins and the bridge's native publication/recovery contract? The proposed decision is [ADR-0020](../design/adr/0020-boinc-buda-evaluation.md). The [spike procedure](../experiments/2026-10-14-buda/README.md) describes the tests still needed.

## What we checked

The repository's base Containerfile pins upstream BOINC at `22bbebe08e2eaac5d5e88a6d93b88e800cb6341c`. BUDA's web pages, scheduler code, local debugging tool, generic remote submission handler and script validators are already present at this commit. No newer server source is necessary merely to expose those features; the running image and project upgrade still need checking.

## What is left

Run the remaining [spike procedure](../experiments/2026-10-14-buda/README.md), including malformed-result rejection, queued-job variant edits, Linux execution and native Mac scheduling. Verify the selected worker digest has the required Linux architecture. Install and configure the Mac client/runtime before an end-to-end task; native wrapper launch alone is insufficient.

Accept or revise ADR-0020 only with those observations, or explicitly decide that the source-confirmed trust and identity changes rule out migration without completing the runtime spike. Keep #481 open in the meantime.
